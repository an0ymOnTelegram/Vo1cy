# Release procedure

Use an Apple Silicon Mac, Swift 6.2 or newer, CMake, and a clean checkout. The application bundle supports macOS 14+. Redux additionally requires macOS 15. This repository's CI uses the standard `macos-15` Apple Silicon runner.

## Public preview

1. Update `Resources/Info.plist`: increment the build number and set the release version. Check model metadata and license links.
2. Run the checks in CONTRIBUTING, build the app, and verify first launch, model loading, recording, text insertion, and single-instance behavior.
3. Run `scripts/package-preview.sh`. This creates a ZIP, drag-to-Applications DMG, and SHA256SUMS in `dist/`. Both app packages are ad-hoc signed and **not Apple notarized**. Publish as a GitHub **prerelease**, with this limitation and platform requirements visible in its notes.
4. Inspect `git diff`, staged files, archive contents, all publicly reachable history, release descriptions, workflow logs/artifacts, and bundle strings for personal data. `scripts/audit-release.py --app /path/to/Vo1cy.app` checks common home paths and credential patterns. `--forbid` adds project-specific private phrases. Automated scans do not replace review.
5. Tag only the sanitized commit. Upload the preview ZIP, DMG, checksums, and release notes through GitHub Releases. Never publish local-development archives, user data, signing keys, benchmark dictations, or ignored directories.

`VO1CY_VERSION` overrides the version; `VO1CY_BUILD` overrides the build number. `VO1CY_PREBUILT_APP` allows packaging a previously built app. Public preview packaging replaces any local development identity with an ad-hoc signature. Do not distribute the identity generated by `install-local.sh`.

Preview updates are manual. Existing users keep their local settings and model files when the application bundle is replaced. macOS may require permissions again after an ad-hoc-signed update.

## Signed and notarized releases

Prerequisites: an Apple Developer ID Application certificate, a Keychain notarytool profile, and a Sparkle Ed25519 signing key. Keep private keys out of the repository and release bundle.

Set `DEVELOPER_ID`, `NOTARY_PROFILE`, `VO1CY_VERSION`, `VO1CY_BUILD`, `VO1CY_FEED_URL`, and `VO1CY_UPDATE_PUBLIC_KEY`, then run `scripts/release.sh`. It signs nested code, submits ZIP/DMG for notarization, staples, verifies, and creates artifacts. It does not upload them.

Use Sparkle's `generate_appcast` with the private update signing key to produce signed enclosure metadata. Publish the ZIP, DMG, and appcast together at the configured HTTPS location. Test upgrade from a prior build, signature rejection, and permission persistence before enabling that channel. The first preview does not configure this channel and cannot claim automatic signed updates.

Official references: [Apple app-opening guidance](https://support.apple.com/102445), [Sparkle documentation](https://sparkle-project.org/documentation/), [GitHub runner reference](https://docs.github.com/en/actions/reference/runners/github-hosted-runners).
